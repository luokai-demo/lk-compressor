# Windows 构建与 Release 发布

## 本机构建

1. 在 Windows 10/11 x64 安装 Python 3.13 x64，创建并激活 `.venv`。
2. 安装 `requirements-dev.txt`。
3. 从目标版本 Release 获取 `windows-build-tools.zip`，使用 `SHA256SUMS.txt` 验证后解压到项目根目录。
4. 执行 `./build.ps1`，输出 `dist/图片压缩工具.exe`。
5. 执行 `python scripts/verify_windows_release.py dist/图片压缩工具.exe`，检查打包后启动与合成资源压缩。

构建流程会保存依赖版本记录，并将工具许可和 Python 包许可嵌入 EXE。构建不需要访问个人资源，不读取开发机历史日志和用户设置。

## GitHub 发布

1. 完成隐私检查、语法检查与核心测试，使用中文提交说明，经 Pull Request 合并至 `main`。
2. 创建版本 Tag 和中文标题、中文说明的**草稿 Release**，上传已审查的 `windows-build-tools.zip`。
3. 在 Actions 中手动运行“Windows 打包发布”，填写目标版本 Tag。
4. 流程只接受 `v数字.数字.数字` 格式，且要求 Tag 与当前工作流提交一致。它会验证工具包校验值、在 Windows 执行真实压缩测试、构建并验证 EXE 启动，上传 EXE、`SHA256SUMS.txt`、`build-dependencies.txt` 与 `THIRD-PARTY-LICENSES.zip`。
5. 确认工作流成功且附件齐全后，再将草稿发布为正式 Release。

工作流使用仓库 `GITHUB_TOKEN`，无需个人访问令牌。发布写权限仅授予手动发布任务；Pull Request 检查不具备发布权限。不要使用 `pull_request_target` 运行贡献者代码。

附件显示标签使用中文；GitHub 会过滤附件文件名中的中文字符，因此实际下载文件名使用英文。

## 发布前检查

- 仓库不含运行日志、编辑器记录、私有素材、凭证或本机路径。
- Git 提交邮箱使用 GitHub noreply；软件“关于”窗口保留作者信息。
- EXE 不提交到 Git，只作为 Release 附件；源码归档由 GitHub 按 Tag 自动生成。
- 确认 `windows-build-tools.zip` 和 `SHA256SUMS.txt` 对应同一批文件。
- 记录真实验证范围；自动合成资源测试不能替代实际 Windows 桌面人工操作验证。
- 旧本机 Git 历史仅作本地参考，不推送旧分支或旧 Tag；正常推送仅针对 `main`。
